# Week 8 — Day 4: Database Indexing & Performance Profiling

## 1. Overview

Day 4 focused on database indexing and query performance profiling.

The goal was to identify query patterns in the Cardiac Patient Monitoring API that frequently filter by `PatientId` and sort by another column, then add appropriate composite indexes and compare query performance before and after the changes.

The work was performed using:

* Entity Framework Core
* SQL Server LocalDB
* EF Core query logging
* Swagger
* Git

---

## 2. Day 4 Objectives

The main objectives were:

* Identify columns or column combinations that genuinely need indexes.
* Add composite indexes for queries that filter and sort together.
* Create and apply an EF Core migration.
* Measure query performance before and after adding the indexes.
* Document the measured results honestly.
* Prepare the Sprint 3 branch for the pull request and mentor review.

## 3. Step 1 — Review the Existing Project

Day 4 started by reviewing the existing API endpoints and looking for frequently used:

* `WHERE` conditions
* `JOIN` conditions
* `ORDER BY` operations
* `FirstOrDefaultAsync()` lookups

The controllers were searched for common query patterns.

The review showed three strong composite-index candidates.

### Candidate 1 — Appointments

The appointments endpoint filters appointments by `PatientId` and sorts them by `AppointmentDate`.

```sql
WHERE [a].[PatientId] = @patientId
ORDER BY [a].[AppointmentDate]
```

Therefore, the selected composite index was:

```text
PatientId + AppointmentDate
```

### Candidate 2 — Medications

The medications endpoint filters medications by `PatientId` and sorts them by `StartDate` descending.

```sql
WHERE [m].[PatientId] = @patientId
ORDER BY [m].[StartDate] DESC
```

Therefore, the selected composite index was:

```text
PatientId + StartDate
```

### Candidate 3 — VitalSigns

The vital signs endpoint filters vital signs by `PatientId` and sorts them by `RecordedAt` descending.

```sql
WHERE [v].[PatientId] = @patientId
ORDER BY [v].[RecordedAt] DESC
```

Therefore, the selected composite index was:

```text
PatientId + RecordedAt
```

## 6. Step 4 — Add Composite Indexes

After identifying the query patterns and recording the baseline measurements, composite indexes were added through the EF Core Fluent API.

The following configuration was added to `CardiacPatientMonitoringDbContext`:

```csharp
// Adds a composite index for patient appointment filtering and date sorting.
modelBuilder.Entity<Appointment>()
    .HasIndex(a => new { a.PatientId, a.AppointmentDate });

// Adds a composite index for patient medication filtering and start-date sorting.
modelBuilder.Entity<Medication>()
    .HasIndex(m => new { m.PatientId, m.StartDate });

// Adds a composite index for patient vital-sign filtering and recorded-time sorting.
modelBuilder.Entity<VitalSign>()
    .HasIndex(v => new { v.PatientId, v.RecordedAt });
```

These indexes were chosen because the corresponding queries use `PatientId` for filtering and another column for sorting.

## 9. Step 7 — Verify the Migration

The migration was reviewed to confirm that it performed the expected database changes.

The `Up()` method removes the previous single-column foreign-key indexes:

```text
IX_VitalSigns_PatientId
IX_Medications_PatientId
IX_Appointments_PatientId
```

and creates the new composite indexes:

```text
IX_VitalSigns_PatientId_RecordedAt
IX_Medications_PatientId_StartDate
IX_Appointments_PatientId_AppointmentDate
```

The migration therefore changes the index structure from:

```text
PatientId
```

to:

```text
PatientId + RecordedAt
PatientId + StartDate
PatientId + AppointmentDate
```

The `Down()` method also correctly restores the previous single-column indexes if the migration is rolled back.

```sql
ON [Medications] ([PatientId], [StartDate]);

ON [Appointments] ([PatientId], [AppointmentDate]);
```

The migration completed successfully.

## 13. Why These Indexes Were Selected

### Appointments

```text
PatientId + AppointmentDate
```

The query filters appointments by patient and sorts them by appointment date.

### Medications

```text
PatientId + StartDate
```

The query filters medications by patient and sorts them by medication start date.

### VitalSigns

```text
PatientId + RecordedAt
```

The query filters vital signs by patient and sorts them by recorded time.

These composite indexes match the actual query patterns instead of indexing columns indiscriminately.

## 17. What I Learned

* Indexes should be added based on real query patterns.
* Frequently filtered and sorted columns can be strong index candidates.
* Composite indexes can match a query that filters and sorts on multiple columns.
* Adding indexes indiscriminately can increase write overhead.
* EF Core migrations provide a controlled way to change database indexes.
* Performance changes should be measured before and after the optimization.
* API response time can include overhead that is unrelated to database execution.
* Small local measurements should be interpreted carefully.
* An optimization should be supported by measured evidence rather than assumptions.
